# 商品マスタ・税計算・会計連携の設計案 🍮

作成：2026-11-08（Asia/Tokyo）。版：`pudding-accounting-design-v0.1`。

**状態：提案・文書のみ。** 商品マスタ、税計算、仕訳生成、会計システム連携は未実装。税率・課税時点・収益認識・失効処理の最終判断は、実際の販売契約、事業主体、適用する会計方針と税務上の確認を踏まえて確定する。参照資料は[SOURCES.md](SOURCES.md)のS19〜S25。

## 1. 検討の結論と未確定事項

| 問い | 設計上の整理 |
|---|---|
| 食品8%かデジタル10%か | 人が食べる実物を提供しない仮想体験は、国内のデジタルサービスとして標準税率10%を第一候補にする。正式な税区分は要確認 |
| 購入時の未確定🍮は何か | 将来の体験提供を約束する前払いなら、前受金・契約負債を候補にする |
| 売掛金を使うか | 未回収の売上債権と、前払いの受領を区別。即時決済では預金または決済代行会社への未収入金が候補 |
| 消費時に売上か | 契約上の履行義務が体験提供で充足される場合の候補。Agentの消費という状態だけで決めない |
| 廃棄時は何を仕訳するか | デジタルの残量廃棄、顧客の権利失効、返金義務の消滅、実際の原価を別々に判定する |
| 税率変更 | 税区分と適用期間付き税率マスタを分離し、過去の税額・仕訳を上書きしない |

以下は販売者側の設計。人間の購入者側の経費処理や、Agent自身の会計帳簿を決める仕様ではない。『売上金』は説明では理解できるが、勘定科目は通常の売上高・役務収益など、接続先の会計方針に対応させる。

## 2. 商品マスタ

| マスタ | 主な項目案 |
|---|---|
| 商品 | `product_id`、SKU、版、名称、販売状態、提供内容、プリセットID・版 |
| 商品の性質 | 仮想体験/デジタルコンテンツ等の取引実態。名称の『食品』と税区分を混同しない |
| 価格 | `price_version`、通貨、整数の最小通貨単位、税込/税抜、適用開始・終了、割引規則 |
| 税区分 | `tax_category_id`、取引地域、判定状態、根拠、確認日、承認者 |
| 税率 | `tax_rule_id`、税区分、国・地域、適用開始/終了、税率の正確な分数、端数処理、版 |
| 会計方針 | `revenue_policy_id`、履行義務、収益認識の契機・方法、失効・返金方針、勘定科目マッピング |
| 利用規則 | 14日・暦の1か月の期限、承認・割当・片付けのポリシー版 |

価格、税率、会計方針の変更は別々に版管理する。税率を商品名やソースコードに直書きしない。同じ税区分・地域に有効な税率が複数重なる設定、適用期間の欠落、未承認の区分を検出したら、自動課税・会計転記を止める。

注文時には商品・価格・提供内容・規則・予定税区分をスナップショット化する。課税時点が注文時より後なら、その課税時点で適用する税率も別に確定・保存する。マスタの現在値で過去の注文を再計算しない。

## 3. 税区分と課税時点

### 3.1 食品と仮想体験

国税庁は軽減税率の飲食料品を、人の飲用・食用に供される食品として説明する[S19]。本サービスのAI用仮想プリンを、その名称だけで食品8%とする根拠にはならない。標準税率10%を第一候補とするのは、実物の飲食料品を提供しないデジタル体験という設計からの推論である。

インターネットを介する電子コンテンツやクラウド利用は、電気通信利用役務の検討対象になる[S20]。日本国内の通常の課税取引を初期検討の範囲とし、海外販売・プラットフォーム経由・返金・無償配布は別の区分と確認事項を持つ。Agentの実行サーバー所在地だけで購入者の取引地域を判定しない。

税率10%・8%は2026-11-08の資料確認時点の説明用の値。将来の変更を固定値の二択で扱わず、適用日と承認済み根拠を持つマスタで選択する。

### 3.2 前払いと、権利の購入

一般の前受金は、受領時ではなく資産の引渡しやサービス提供時が消費税上の原則的な時期となる[S21]。ただし、本商品が購入時にデジタル利用権を提供する契約なのか、後日の体験提供の前払いなのかを先に定める。

商品券等の説明も参考になるが[S22]、仮想プリンが自動的に物品切手等に該当するとはしない。発行者の前払受領、商品券等の譲渡、サービス提供を区別し、『購入時は全部非課税』と一括設定しない。

会計の収益認識日、消費税の課税日、決済成立日、入金日、請求書発行日は別項目とする。会計と税務の時期が一致すると確認できた場合だけ、そのルールを適用する。

### 3.3 金額と丸め

JPYは整数円、率や配分計算は有理数またはDecimalとし、二進浮動小数で金額を扱わない。税込と税抜、値引き後の課税対象額を区別する。税率は合計だけでなく、必要に応じて国税・地方税の内訳も保持する。

適格請求書の消費税額等は、一の請求書につき税率ごとに一回の端数処理が必要である[S24]。商品ごと・一口ごとに丸めた税額を合計して、請求書の正式税額にはしない。請求書で確定した税額を明細へ配賦する場合は、配賦の残差を保持して合計を一致させる。

税率変更をまたぐ前払いでは、課税時点、経過措置、税込価格を固定するか税抜価格を固定するかを確認する。注文時の見込税率と、課税時点で確定した税率を保持し、差額は承認済みの価格・税務方針で処理する。

## 4. 収益認識と仕訳

ASBJの適用指針第52〜56項は、前払と契約負債、履行に伴う収益認識、顧客が行使しない権利を扱う[S23]。この考え方を参照するが、事業主体に適用する会計基準は別途確認する。

### 4.1 約束する提供内容で方針を選ぶ

| 契約の候補 | 会計方針の検討 |
|---|---|
| 購入時に利用権・デジタル商品を提供して義務を充足 | 購入・権利提供時の収益認識を検討。必ず消費まで繰り延べるとは限らない |
| 将来の一回の体験提供を約束 | 前受金・契約負債を認識し、承認した履行の契機で収益へ振り替える候補 |
| 期間中の利用可能性・待機サービスを提供 | 一定期間での収益認識や複数義務への価格配分を検討 |

どれを採用するかは未確定。`begin`、最初の一口、完食、利用期間の経過のどれを履行の証拠にするかも承認済みの契約へ合わせる。片付け忘れでセッションが閉じないことだけを理由に、既に提供したサービスの売上を無期限に保留しない。

一口のmgは技術上の残量であり、財務上の履行割合ではない。比例認識を採用する場合も、商品価値をどう配分するかの根拠が必要である。初期案は一個単位の会計イベントとし、一口ごとの自動仕訳を前提にしない。

### 4.2 消費税を省略した概念例

将来の体験への前払い1,000円、体験を提供した時点で売上認識する方針を仮定する。**税の省略は免税・非課税という意味ではない。**

| 事象 | 借方 | 貸方 |
|---|---|---|
| 顧客の支払を受領 | 預金または決済代行未収入金 1,000 | 前受金・契約負債 1,000 |
| 契約上の体験提供を完了 | 前受金・契約負債 1,000 | 売上高 1,000 |
| 未提供のまま権利が失効し、返金等の義務も消滅 | 前受金・契約負債 1,000 | 失効に係る収益 1,000（表示科目は要確定） |
| 提供前に全額返金 | 前受金・契約負債 1,000 | 預金または返金未払金 1,000 |

『未確定🍮』は内部の補助科目名として使えるが、会計システム上は前受金・契約負債との対応を固定する。売掛金は未回収の売上債権の科目なので、即時前払いと混同しない。決済代行会社の入金待ちも、顧客の売掛と別にする。

### 4.3 税率10%を仮定した支払・提供の例

国内課税サービス、税込1,100円、提供時に課税・収益認識、手数料なし、という条件を仮定する。正式な税務判断・科目の採用前には転記しない。

| 事象 | 借方 | 貸方 |
|---|---|---|
| 決済成立 | 決済代行未収入金 1,100 | 前受金 1,100 |
| 契約上のサービス提供 | 前受金 1,100 | 売上高 1,000 ＋ 仮受消費税等 100 |
| 決済代行会社から入金 | 預金 1,100 | 決済代行未収入金 1,100 |

決済手数料がある場合は、顧客に対する総額と決済代行からの純入金を分け、手数料の契約と税区分に応じて別に記録する。

### 4.4 廃棄と失効は別の事象

14日到達後も違反を伴う使用が可能という現在の規則では、14日を過ぎただけで全ての義務が消えたとは断定できない。暦の1か月で使用できなくなった時も、返金義務や契約条件を確認して失効に係る収益の可否・時点を決める。

| 状況 | 必要な処理 |
|---|---|
| 仮想の残量を捨てる | 廃棄量と理由を記録。会計仕訳の要否は履行・負債・原価の状態から別に決める |
| 未提供で返金義務等が残る | 前受金や返金負債を維持。廃棄しただけで収益化しない |
| 未提供・権利と関連義務が消滅 | 承認済み方針に従い負債から失効に係る収益へ。税区分は別途確認 |
| 既に一個分を収益認識済み | 同じ対価を廃棄・失効でもう一度売上にしない |
| 部分提供してから失効 | 配分済みの認識額と未認識残高を照合し、残高だけを対象にする |
| 実際に資産計上した原価がある | 原価の帳簿価額の処理を別に検討。仮想mgから棚卸資産廃棄損を作らない |

ASBJでは非行使部分を権利行使のパターンに比例して収益認識する場合などもある[S23]。常に期限日に全額を雑収入にする仕様には固定しない。未提供失効の消費税についても、自動で『10%売上』『非課税』『不課税』のいずれかに決めず、承認待ちの税務判定を持つ[S25]。

日次ジョブが翌日に動いても、`right_expired_at`と`disposal_processed_at`は区別する。仕訳日をバッチ実行日から機械的に作らない。月末・決算期をまたぐ場合は、会計方針で承認した発生時点を使う。閉鎖済み会計期間への遡及転記は審査へ回す。

## 5. 会計システムとの連携

Puddingは購入・提供・返金・権利失効・廃棄の業務事実と、その対価の配分を持つ。総勘定元帳と正式な会計伝票は接続先が正本を持つ。会計API・CSV形式・科目コードはアダプターで対応し、接続先は未選定である。

| 会計連携イベント案 | 内容 |
|---|---|
| `payment_confirmed` | 決済の検証済み成立、注文・購入物との対応 |
| `performance_satisfied` | 契約上の義務・提供根拠・配分した金額 |
| `right_expired` | 消滅した権利、未認識残高、残存義務、実効時刻 |
| `refund_confirmed` | 返金と元取引・元税額の参照 |
| `disposal_recorded` | 残量の廃棄。収益認識を直接意味しない |

仕訳候補は元イベント、注文、商品・価格・税・会計方針の版、発生日時・記録日時、会社・帳簿、借方貸方、金額、税区分、承認状態を保持する。Agentの名前や会話だけで会計の取引先や会社を決めない。

業務イベントと送信待ち記録を同じDBトランザクションで確定し、連携アダプターが送る。会計側の失敗で食べた一口を巻き戻して再実行しない。受信側の冪等キーと伝票番号で照合し、受領結果不明の場合は照合してから再送する。受信側に冪等性・照合手段がなければ、確認なしの自動再送はしない。

同じ業務イベントから同じ会社・帳簿・仕訳種別の伝票を二重作成しない。新しい会計ルール版に切り替えただけで、過去のイベントを再転記しない。修正は元伝票を参照する取消・逆仕訳・再計上として履歴を残す。

Agentは会計方針・税率・科目・過去伝票を自由に変更できない。税区分と方針の承認、期間の締め、例外的な転記・訂正は人間の管理操作にする。税務判定が未承認の候補を正式伝票として自動送信しない。

## 6. 確定前に残す判断事項

1. 販売者の事業主体・課税関係・採用する会計方針、請求書の発行条件。
2. 商品の実態、国内/国外、標準税率の適用、前払い・利用権・物品切手等の分類。
3. 購入者へ約束する履行義務と、購入時・体験提供時・期間配分のどれで収益を認識するか。
4. 課税時点と税率変更時の価格・経過措置・請求書の扱い。
5. 部分使用・期限切れ・返金・サービス障害時に残る義務と、その会計・税務処理。
6. 失効に係る収益の表示科目・税区分と、実際に資産計上する原価の有無。
7. 会計連携先、科目・税コード、承認、締め・訂正、再送と照合の方法。

仕様書は検討根拠を残すもので、税理士等による実契約の確認の代わりにはしない。未確定事項をデフォルト値で埋めて販売・自動転記へ進めない。
